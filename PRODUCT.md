# Glint product context

## Register

brand

This register applies to the public product site. The Windows application keeps its native product interface.

## Users

Windows users working with many Chrome and Edge tabs across windows and browser profiles. They need to locate an already-open page without inspecting each window.

## Product purpose

Provide one keyboard-accessible search window for connected browser tabs. Search matches titles and URLs; selecting a result returns to its browser tab and window.

## Brand personality

Formal, clear, practical. Describe actual functionality and installation requirements. The user approved direct explanatory copy rather than slogans, rhetorical questions or conversational marketing.

## Design principles

- Explain the fragmented-tab problem with browser-window imagery.
- Demonstrate the complete search and activation workflow with real product screenshots and explicitly labeled sample data.
- Guide first-time setup with browser-specific steps and illustrations.
- Keep the product site focused on the product; keep code and build guidance in the README and developer documentation.
- Preserve the blue-and-white identity documented in docs/branding.md.

## Anti-references

Avoid changelog-shaped READMEs, marketing buzzwords, fabricated performance numbers, decorative feature-card grids and screenshots that misrepresent the product.

## Accessibility and inclusion

Provide keyboard access, visible focus, descriptive alternative text, readable contrast, responsive layouts and reduced-motion support. Installation instructions must distinguish Chrome and Edge and explain extension loading per profile.
