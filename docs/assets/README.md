# Product image provenance

The PNG images in this directory were rendered on Windows on 2026-10-22 from
Glint's native C++ interface code at 96 DPI. They show the application's client
area; the operating system's outer title bar and window frame are omitted.
The search examples include Glint's client title bar and inset close button,
updated from the local validation build for the search feedback changes.

Each PNG also has an English-language `-en.png` variant, rendered from the same
source and layout. The English search image uses “design” with four matching
example tabs. The product website selects the matching language automatically.

## Rendering method

A task-local fixture under the ignored `.local/render/` directory instantiated
the native windows and controls without entering Glint's desktop application
startup. The fixture exposed creation and rendering methods in local source
copies, used distinct window class names, and omitted tray and hotkey lifecycle
code. The application's layout, fonts, text, colors, control drawing and setup
illustrations came from its native source, including `src/ui_theme.hpp` and
`src/setup_illustration.hpp`.

The rendering thread used a separate Win32 desktop that was never displayed.
Every top-level window remained hidden. A thread hook vetoed focus and
activation, and the fixture checked window visibility and DPI before and after
each export. The native `WM_PRINTCLIENT`, `WM_PRINT` and `WM_DRAWITEM` handlers
drew into a memory bitmap, which GDI+ encoded as PNG. No screenshot was taken
of the user's desktop or existing application windows.

The fixture redirected HKCU and LOCALAPPDATA to temporary, process-local test
locations and removed them afterward. It did not start Glint's desktop loop,
create a tray icon, register a global shortcut, start a pipe server, launch a
browser, load an extension, or change a user's browser profile or Glint settings.

## Example data

The search and connected-state images use sample messages applied directly to
the real in-memory `TabIndex`. Their profile labels explicitly include “示例” or “example”,
and every sample URL uses `https://example.com/`. The folder-selection image
uses `C:\Users\Example\AppData\Local\Glint\browser-extension` as an illustrative
path. No real browsing data is included.

These images document native interface appearance. They are not recordings of
a live browser connection, tab activation, or keyboard-focus test. Public
captions should identify them as native interface renders with example data.

## Vector illustrations

`tab-overload.svg` and its English variant `tab-overload-en.svg` are explanatory illustrations of three browser windows and
their separate profiles. `architecture.svg` and its English variant
`architecture-en.svg` explain local extension, bridge and desktop communication.
These SVGs are not application screenshots. The brand logo and banner are generated by
`scripts/generate-brand-assets.py`.
